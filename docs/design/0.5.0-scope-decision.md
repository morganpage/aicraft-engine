# Decision: `aicraft-engine@0.5.0` Scope Expansion

> Date: 2026-08-10
> Status: **PUBLISHED** — `aicraft-engine@0.5.0` live on npm (2026-08-10T12:37:10.635Z)
> Author: Engine Lead (orchestrator)
> Supersedes (in part): the release scope described in
> `docs/design/character-enemy-validation-release-candidate.md` and
> `docs/design/post-0.4-character-enemy-validation-plan.md`, which scoped 0.5.0
> to humanoid + charger only. Those docs remain the audit trail for the original
> candidate; this doc records the deliberate scope expansion and the B1 release
> strategy.

## The decision

**Expand `0.5.0` to ship the entire current `main` tree** (Option B/B1), rather
than publishing the narrow humanoid+charger candidate originally defined and
splitting the rest into 0.6.0.

Original 0.5.0 candidate scope (per `post-0.4-character-enemy-validation-plan.md`):
humanoid body plan + charger archetype only.

Actual 0.5.0 scope (what ships):

| Surface | Module | Status in 0.5.0 |
|---|---|---|
| Humanoid body plan | `src/character/humanoid/` | **Idle pose polished (Phase H2 APPROVED).** Grounded locomotion (H3), airborne + landing (H4), and ceiling-gravity support are **stub geometry, deferred to 0.6.0.** The idle-pose sheet (`benchmarks/character-body-plans/humanoid-idle-h2.png`) is approved; the motion panels render idle-equivalent today and are honestly labelled `(0.6.0)`. |
| Charger archetype | `src/platformer/enemy/archetypes/charger.ts` | **Shipped, visually APPROVED.** All four phases (patrol/windup/dash/recovery) legible, telegraphed through shape not colour. |
| Collision line-of-sight | `src/collision/los.ts` | Shipped. |
| Procedural terrain art | `src/terrain-art/` | Shipped — dual-grid authoring, manual paint, rule-atlas composition, runtime renderer. `./terrain-art/editor` subpath export. |
| LDtk native pipeline | `src/ldtk/` | Shipped — parse/edit/render/write `.ldtk`, auto-layer rule engine proven against a 20,046-tile oracle. |
| Aseprite-JSON sprites | `src/sprites/` | Shipped — defensive parser, compile, resolve, render, character-agnostic anim-state. |
| Ladder / climb system | `src/platformer/abilities/climb-ability.ts` + kernel ladder support | Shipped. |
| Tile semantics from IntGrid | `src/level/tile-semantics.ts` | Shipped. |

## Why B1 (ship now, defer humanoid motion to 0.6.0)

1. **The narrow candidate's blocker was humanoid motion, and it is not a quick
   fix.** `@benchmarker`'s fresh verdict (2026-08-10): charger APPROVED;
   humanoid idle APPROVED but Phase H3/H4 are unimplemented stubs in
   `src/character/humanoid/pose.ts`. Completing H3+H4 is a real multi-step
   implementation effort with its own plan (`humanoid-visual-revision-plan.md`)
   and visual-review gates. Holding 0.5.0 for it would leave the package
   unpublished indefinitely while a large amount of finished, tested,
   unrelated work (LDtk, sprites, ladders, terrain-art) sits unreleased.
2. **The shipped surface is already a strong 0.5.0 on its own.** LDtk parity
   (20,046-tile oracle), the Aseprite pipeline, the climb system, and
   terrain-art each stand alone as headline features. The humanoid ships as an
   honest idle-polished preview with motion explicitly deferred.
3. **The 12-day-old unpublished state is itself a risk.** `package.json` and
   `package-lock.json` have read `0.5.0` since 2026-07-29 while npm `latest` has
   remained `0.4.0`. Releasing closes that drift.
4. **Motion poses get a proper R&D loop in 0.6.0** rather than being rushed to
   hit a release date.

## Size-gate re-baseline

`scripts/check-level-visual-size.mjs` measured the **entire `dist/`** against a
baseline frozen at the **Phase 0 level-visual-rendering milestone** (1.66 MB
total). Despite the historical name, the check is a whole-distribution budget.
On the 0.5.0 tree it reported `+39.52%` over the Phase 0 ceiling — entirely
from legitimate module growth (`sprites/`, `ldtk/`, `terrain-art/`,
`character/humanoid/`, the LDtk rules engine), not bloat.

The baseline is re-pegged to the 0.5.0 `dist/` (total 2,319,394 / js 1,423,685 /
declarations 895,709) with the existing headroom ratios (10% total/decl, 12%
js) preserved. The gate now serves as a **regression budget for future growth**
(0.5.x patch lines and into 0.6.0); it re-baselines at each minor release. The
script header documents this. Phase 0 numbers are preserved as historical
record in `docs/design/level-visual-rendering-phase0-record.md`.

A future cleanup (out of scope for 0.5.0) could either rename the script to
`check:dist-size` or rescope it to measure level-visual files only, honouring
the original name. Deferred.

## Deferred to 0.6.0

- Humanoid grounded locomotion (Phase H3): displacement-driven gait blending,
  named contact/passing/opposite-contact poses, counter-swinging passive arms.
- Humanoid airborne + landing (Phase H4): ascent/apex/descent geometry,
  landing compression, ceiling-gravity support.
- Rewrite of `benchmarks/_scripts/humanoid-validation-render.ts` to render the
  full named-gait + landing sheet once H3/H4 land (the 0.5.0 fix only removed
  the obsolete prototype-equality assertion and labelled stub panels honestly).

The 0.5.0 public API for the humanoid (`deriveHumanoidConfig`,
`createHumanoidVisualState`, `advanceHumanoidVisual`, `drawHumanoid`, etc.) is
**stable and will not change** in 0.6.0 — only the stub pose geometry fills in.
Consumers coding against the 0.5.0 humanoid API will get correct motion
rendering in 0.6.0 with no API changes.
